## Rollback

**Se rompe DOPO lo swap** — lo script stampa i comandi esatti a fine run. In sintesi:
```powershell
$nssm = 'C:\ProgramData\chocolatey\bin\nssm.exe'
& $nssm stop PresenzeHR confirm
$bak = Get-ChildItem 'E:\www\hr.bak-*' -Directory | Sort Name -Desc | Select -First 1
Remove-Item 'E:\www\hr' -Recurse -Force
Move-Item $bak.FullName 'E:\www\hr'
& $nssm start PresenzeHR
```
**Il DB NON va rollbackato:** la migrazione è additiva, il vecchio codice ignora le colonne/tabella nuove. (Se proprio vuoi tornare al DB pre-release: `E:\HR\backups\prod-<timestamp>.db` dal passo 2.)

## Note / trappole (dai precedenti incidenti)
- Mai fare rename/move a mano di `E:\www\hr`: contiene la subdir **`iis\`** (physicalPath del sito IIS) e **`public\uploads\`** (avatar runtime). Lo script li preserva — un move manuale no → 500.19 (incidente 2026-04-17, ~40 min down).
- Config prod vera = NSSM `AppEnvironmentExtra`, non `.env`. Lo script ripristina il `.env` dal backup ma è quasi-placeholder.
- Server multi-tenant IIS (~25 siti): non toccare config IIS globale.
